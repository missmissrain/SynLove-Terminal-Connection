# SynLove-Terminal-Connection

SynLove 的终端连接组件。将电脑登记为可发现、可控制的设备，通过已有 VPS 中转与服务器通信，集中提供远程命令、本机音乐播放和编码任务完成通知。

终端可以独立常驻，无需启动该电脑上的 SynLove 主程序、GUI 或模型。服务器统一维护设备登记与通知交接，终端只维护本机执行日志、待发事件和播放状态。

## 功能

- 设备登记、签名心跳、在线状态与能力查询。
- Windows CMD、Linux Shell 远程命令执行，输出有界，最长执行期限120秒。
- 通过已有 SSH 隧道执行 SFTP 双向文件搬运、目录浏览与设备间转发，传输后校验 SHA-256，默认禁止覆盖。
- 接收服务器解析的音乐地址，在目标电脑的交互用户会话中播放；支持暂停、继续和停止。
- 只读观测本机 Codex、OpenCode 会话完成状态，将结果经 VPS 上报服务器。
- 编码完成事件及命令结果持久保存；断线后重传，使用稳定业务 ID 去重。
- 首次接入在终端生成 Ed25519 私钥，仅回传公钥；支持一次性接入文件与 Windows 登录自启。
- 预留安卓、ADB、嵌入式设备与接入网关的登记结构。

ADB 执行、安卓原生客户端、嵌入式固件与子设备转发适配器尚未实现。预留设备不会自动显示在线，也不能接收尚未实现的执行指令。

## 通信方式

服务器管理器向现有 VPS 注册 `terminal.connection` 能力。终端通过 HTTPS 任务 API 提交带签名的心跳、完成通知及命令结果，服务器在签名回执中返回待执行命令。

VPS 负责中转，不负责生成终端私钥或执行目标电脑的命令。服务器本机管理 API 与终端本机接口均只监听回环地址，不直接暴露到公网。

| 默认端口 | 所在位置 | 用途 |
| --- | --- | --- |
| `443` | VPS | HTTPS/WSS 中转入口，沿用现有部署配置 |
| `17864` | 服务器回环地址 | 设备管理、配对、命令提交与结果查询 |
| `17863` | 各终端回环地址 | 音乐控制与完成通知本机入口 |

VPS 必须支持 `/v1/tasks`、`/v1/tasks/:id` 与 `/ws/node`。实际 HTTPS 端口与私有 CA 按部署环境配置，不关闭证书或主机名验证。

## 运行准备

使用已有 Python 环境，依赖见 `requirements.txt`。运行时需要 `cryptography`、`websocket-client`；保留的 SSH 维护兼容模块使用 `paramiko`。音乐功能另需 `ffplay`，缺少播放器时仍可运行终端通信及远程命令。

本项目的 Windows 安装器检查已有依赖，不自动下载或重装 Python 环境。Linux 可使用统一 Python 启动入口，系统服务需按发行版配置。

## 部署服务器管理器

1. 将 `config/ServerConfig.example.json` 复制为私有 `config/ServerConfig.json`。
2. 填写现有 VPS 地址、令牌、本机管理令牌及运行目录。使用私有 CA 时增加 `tlsCaFile`。
3. 若需将完成结果交给 SynLove 的 QQ 出站队列，填写 `notificationInbox` 与 `notificationTarget`。
4. 执行 `scripts/InstallTerminal.ps1 -Server -Python <已有Python路径>`。

安装器注册 `SynLoveTerminalServer` 用户登录计划任务，并验证管理器健康接口及 VPS 连接。管理器可用不代表消息已经发到用户端，通知最终投递仍取决于 SynLove 的出站通道。

## 接入一台 Windows 终端

1. 在服务器管理接口为该设备生成一次性接入文件。
2. 将文件私下交付目标设备，保存为仓库根目录的 `Pairing.json`。
3. 双击 `Install.cmd`，或运行 `scripts/InstallTerminal.ps1 -Bundle <接入文件> -Python <已有Python路径>`。

安装器在本机生成密钥并回传公钥，验证服务器签名后保存终端配置，再注册 `SynLoveTerminalClient` 登录计划任务。已存在身份时复用，不覆盖私钥或重复配对。

接入码有效期十分钟，只允许绑定一个公钥。同公钥可在有效期内重新领取配对回执，避免断网导致登记已成功而本机配置未保存。接入文件包含私有中转凭据，应通过私人通道交付并限制读取权限。

当前自动接入配置会启用目标电脑的命令执行。仅将接入文件交付给本人管理、允许服务器控制的设备；需要禁用命令能力时将终端私有配置的 `shellEnabled` 设为 `false`。

计划任务使用交互用户会话，适合桌面播放与当前用户的编码记录。Windows 注销后不保证音频与该用户会话继续可用。

## 管理与工具接口

服务器管理 API 使用 `Authorization: Bearer <本机管理令牌>`：

| 方法与路径 | 用途 |
| --- | --- |
| `GET /v1/health` | 管理器健康、PID 与 VPS 连接 |
| `GET /v1/devices` | 公开设备字段、在线状态与能力 |
| `GET /v1/deviceTypes` | 设备类型及接入适配器支持范围 |
| `POST /v1/device/reserve` | 预登记安卓、嵌入式或其他设备 |
| `POST /v1/pair` | 生成支持的直连终端接入文件 |
| `POST /v1/device` | 修改名称、启用状态及通知开关 |
| `POST /v1/commands` | 持久提交一次设备命令 |
| `GET /v1/commands/:id` | 查询同一命令结果，不重新执行 |

MCP 入口为 `terminalConnection/tools/TerminalMcp.py --config <管理配置路径>`，提供 `terminal_devices`、`remote_cmd_list`、`remote_cmd_probe`、`remote_cmd_run`、`terminal_music`，以及 `remote_file_targets`、`remote_file_list`、`remote_file_transfer`。设备列表同时返回 `fileTargets`，未配置 SSH 的设备不会被当作可传输。点歌和酷狗曲目解析仍由服务器上的酷狗工具完成。

文件传输沿用 SSH 的地址、凭据和主机指纹，不新增监听端口。默认单文件上限 256 MiB，父目录须已存在，完整性验证成功后才原子提交。`local` 是 MCP 所在机器，使用前需按设备列表确认方向。详见 [文件传输说明](docs/FileTransfer.md)。

SynLove 主程序通过私有 `config/terminalConnection.json` 指向本仓库与服务器本机管理 API。主程序保留 GUI/API 代理和 MCP 注册，不再运行本机编码完成观察者。SSH 维护兼容代码位于本仓库 `remoteControl`，日常设备控制使用签名终端协议。

本机终端接口使用终端自己的本机令牌：

- `POST /v1/music`：提交音乐操作。
- `POST /v1/notify`：接收 `codex` 或 `opencode` 来源的最终摘要，持久入队后返回确认。

完成通知还需要在服务器私有配置中设置 `notificationInbox` 与 `notificationTarget`。前者指向主程序的 `runtime/dsh/backendNotifications`，后者填写 QQ 接收者标识；两项均不得提交到仓库。设备上的 Codex、OpenCode 通知开关分别控制对应来源。缺少目的地时，已启用来源的通知保留在服务器待发箱；已关闭来源的通知会被消耗，之后开启不会补发这些旧事件。接口的入队确认仅表示持久接收，实际到达聊天需由主程序发送链路确认。

设备字段和安卓、嵌入式预留约定见 [设备登记说明](docs/DeviceRegistration.md)。

## 稳定性与权限

服务器和终端都保留 SQLite 业务去重记录。已开始执行但因重启或失联无法确认的命令返回“结果未知”，不会自动重新执行。命令超时后可能仍有子进程运行，返回结果会明确标识，不将超时当作撤销成功。

签名正文使用 `base64-json` 封装，签名头使用整数时间戳，避免经过 JavaScript 中转时 `0.0` 被转换为 `0` 导致验签失败。服务器兼容升级期间的旧心跳格式；新终端与新回执使用不可变封装。待发箱按总字节数分批，防止封装后超过协议上限。

同机进程通过回环端口独占防止重复启动；服务器另用设备启动租约防止同一身份被多台机器同时使用。完成通知只投递服务器既有队列，不在终端新建微信或 QQ 消费者。

终端非正常退出后，新实例可能需等待90秒租约过期。计划内升级应先确认旧进程和本机监听已退出，读取 `GET /v1/instance/:id` 的启动ID，再以该ID调用 `POST /v1/instance/release` 释放旧租约。管理器会比对实例ID，拒绝释放已经变化的实例；不要对仍在运行的终端使用此管理接口。

该接入方案沿用同一所有者的 VPS 凭据与设备信任关系，不提供多租户隔离。不要公开真实配置、接入文件、私钥或运行数据库。

## 验证

运行 `python -X utf8 -m unittest discover -s tests -p "*Tests.py" -v` 执行隔离测试，不调用模型或发送真实社交消息。

运行 `scripts/BuildRelease.py` 可生成仅包含源码、测试、文档与示例配置的归档；不包含运行依赖、身份、聊天记录或私人连接配置。
